# Database Implementation Plan — System Design (Student Management System)

> Status: **Draft for review** — no implementation yet.
> Target stack: C# WinForms (.NET Framework 4.7.2) + MySQL via XAMPP.

---

## 1. Goal

Replace the current hardcoded login and empty data stubs with a real MySQL-backed
data layer, starting with authentication and a `users` table. Everything else in the
Student Management System stays UI-only for now.

## 2. Current State (verified)

| Area | What exists today |
| --- | --- |
| Login | `Form9`, `Form10`, `Form11` check `username == "admin" && password == "12345"` inline. |
| Stubs | `MySqlConnection.cs`, `MySqlCommand.cs`, `MySqlDataReader.cs` → `NotImplementedException`; `Database.cs`, `Username.cs`, `Password.cs` are empty. |
| Driver | **None.** Only FakeItEasy + Castle.Core (mocking) are referenced. |
| Config | `App.config` has no connection string. |
| Target | `.NET Framework v4.7.2`, WinForms, AnyCPU. |

## 3. Key Architectural Decision — Remove the Stubs

The stub classes are named `MySqlConnection`, `MySqlCommand`, `MySqlDataReader` in the
`System_Design` namespace. The official MySQL connector exposes **types with the same
simple names** in `MySql.Data.MySqlClient`. Adding the driver while keeping the stubs
produces ambiguous-type references wherever both are imported.

**Decision:** delete `MySqlConnection.cs`, `MySqlCommand.cs`, `MySqlDataReader.cs`
(and repurpose `Database.cs`, `Username.cs`, `Password.cs`). Use the real driver.

> These stubs were scaffolding. They cannot coexist with a working connector.

## 4. Environment Setup (XAMPP)

1. Start **MySQL** from the XAMPP Control Panel.
2. Default connection parameters (local dev):
   - Host: `localhost`
   - Port: `3306`
   - User: `root`
   - Password: *(empty)*
3. Create the database:
   ```sql
   CREATE DATABASE IF NOT EXISTS student_management
     CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```

## 5. Driver & Configuration

- Install **`MySql.Data`** (official Oracle connector) via NuGet.
  *(Alternative: `MySqlConnector` — faster, MIT-licensed, drop-in. Pick one, not both.)*
- Add a connection string to `App.config`:
  ```xml
  <connectionStrings>
    <add name="StudentDb"
         connectionString="server=localhost;port=3306;user=root;password=;database=student_management;SslMode=None;"
         providerName="MySql.Data.MySqlClient" />
  </connectionStrings>
  ```

## 6. Data Layer Design

Keep ADO.NET behind a small repository so the WinForms UI never talks SQL directly.

```
System_Design
├── Data/
│   ├── Database.cs          // connection factory: reads App.config, opens/closes
│   ├── UserRepository.cs    // ValidateCredentials, CreateUser, etc. (parameterized)
│   └── ...
```

- **`Database`** — helper that returns an open `MySqlConnection` from the configured
  connection string. `using` blocks guarantee disposal.
- **`UserRepository`** — all queries use **parameterized statements** (`@username`,
  `@password`) — never string concatenation. This is the SQL-injection guardrail.
- **`Password` / `Username`** — repurpose as a small validation helper if needed, or
  remove if redundant.

## 7. Schema (Phase 1 — Authentication)

```sql
CREATE TABLE IF NOT EXISTS users (
    id            INT UNSIGNED NOT NULL AUTO_INCREMENT,
    username      VARCHAR(50)  NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,      -- never plaintext
    role          VARCHAR(20)  NOT NULL DEFAULT 'user',
    created_at    TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

Seed one admin for initial login:
```sql
-- password: use a salted hash generated by the app, do NOT insert "12345"
INSERT INTO users (username, password_hash, role)
VALUES ('admin', '<bcrypt-or-sha256-hash>', 'admin');
```

## 8. Password Handling

- **Never store or compare plaintext.** Current `"12345"` logic must go.
- Use a salted hash (e.g. **BCrypt** via `BCrypt.Net-Next`, or PBKDF2).
- Login flow: fetch the stored hash for the username → verify against the supplied
  password → never reveal *which* part failed (avoid user-enumeration hints).

## 9. Implementation Phases

| Phase | Work | Exit criteria |
| --- | --- | --- |
| P0 | XAMPP MySQL running; DB created | `mysql -u root -e "show databases"` shows `student_management` |
| P1 | Add `MySql.Data`; delete stub files; add connection string | Project compiles with real driver |
| P2 | Implement `Database` + `UserRepository` + seed script | Unit-testable, parameterized queries |
| P3 | Replace hardcoded login in `Form9`/`Form10` | Login validates against DB, wrong creds rejected |
| P4 | Password hashing + seed admin | No plaintext stored; admin logs in |

## 10. Risks & Open Questions

- **Stub removal** is a breaking change — confirm nothing else references them (verified: only the stub files themselves).
- **Which driver**: `MySql.Data` vs `MySqlConnector` — pick one.
- **Password hashing library**: BCrypt.Net-Next (recommended) vs built-in PBKDF2.
- **Scope**: this plan covers only auth. The full Student/Course/Enrollment model is a
  later change once the data layer and pattern are proven.
- **Testing**: no test project exists in the solution yet. Add a unit test project so
  `UserRepository` can be tested against a fake/in-memory seam without a live DB.
